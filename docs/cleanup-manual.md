# ハンズオン用 リソース一括削除マニュアル（CloudShell）

ハンズオン学習後に作成したリソースを、毎回きれいに一括削除するための手順です。
**第2回（Day1）・第3回（Day2）・第4回（Day3）のどの時点でも、手動で作ったものも CloudFormation で作ったものも、同じ手順で消えます。**

---

## 削除の正しい順番（依存関係のルール）

AWS のリソースは「VPC の中にサブネット、サブネットの中に EC2」のように入れ子になっていて、中に何かが残っている箱は消せません。
消すときは一番内側から外側へ、しかも**前の段階が「消え終わる」のを待ってから**次へ進みます。第2回で学んだ「作る順番は外側から内側へ」の逆です。

| 順番 | 消すもの | 待つこと |
|---|---|---|
| 1 | EC2 インスタンス（Web / DB / 自分で足したもの） | 「終了済み」になるまで（1〜2 分） |
| 2 | NAT ゲートウェイ | 「削除済み」になるまで（2〜5 分）。これが終わらないと Elastic IP も IGW も消せない |
| 3 | Elastic IP | NAT に付いていたものを解放。**Notion 5 章の手順で作った EIP には名前が付いていない**ので、名前で探すと見落とす |
| 4 | ネットワークインターフェース・VPC エンドポイント | インスタンスや NAT の残骸が消えるまで |
| 5 | IGW → セキュリティグループ（default 以外）→ サブネット → ルートテーブル（メイン以外）→ **VPC** | |
| 6 | CloudFormation スタック（テンプレートを使った人だけ） | 中身はもう無いので数十秒 |

---

## CloudShell で実行する（1 コマンド）

1. AWS コンソール右上の **CloudShell アイコン（`>_`）** をクリックする
2. 画面右上のリージョンが **東京（ap-northeast-1）** になっていることを確認する
3. 次の 1 行を貼り付けて Enter

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/NittaYuya/aws-handson-cloudformation/main/scripts/cleanup.sh)
```

4. 消す対象の一覧が表示されるので、内容を見て **`yes`** と入力する

```
------------------------------------------------------------
 削除対象  リージョン: ap-northeast-1  キーワード: *kikagaku*
------------------------------------------------------------
 VPC                : vpc-0123456789abcdef0
 EC2 インスタンス   : i-0aaa… i-0bbb…
 NAT ゲートウェイ   : nat-0ccc…
 Elastic IP         : eipalloc-0ddd…
 VPC エンドポイント : なし
 CloudFormation     : kikagaku-stage2
 （VPC の中のサブネット・IGW・SG・ルートテーブルも一緒に消えます）
------------------------------------------------------------
上のリソースをすべて削除します。よければ yes と入力:
```

5. 各段階の完了を待ちながら進みます（NAT がある場合は全体で 5〜8 分）。最後に「完了」と出れば終わりです
6. **翌日以降に請求ダッシュボード**（右上のアカウント名 → 請求とコスト管理）で、EC2・NAT・EIP の行が増えていないことを確認する

### 対象になるもの・ならないもの

- 対象: 名前に `kikagaku` を含む VPC とその中身すべて、名前に `kikagaku` を含む EC2 / NAT / Elastic IP、名前に `kikagaku` を含む CloudFormation スタック
- 対象外: デフォルト VPC、名前に `kikagaku` を含まない VPC、キーペア（`kikagaku-cli-key` は課金されないので残して構いません。不要なら EC2 → キーペアから手で削除）

---

## ポイント・注意点

1. **途中で止まっても、もう一度同じコマンドを実行すれば続きから消えます。** 何度実行しても安全です。VPC の削除だけが `DependencyViolation` で失敗した場合は、AWS 内部の解放待ちなので 2〜3 分置いて再実行してください。
2. **「未使用の Elastic IP が残っています」と出たら**、名前が付いていない EIP が別にあるということです。自分のものなら VPC → Elastic IP から「解放」してください。使っていなくても課金されます。
3. **CloudFormation で作った人**は、テンプレートの中身を先に消してからスタックの記録を消す順になっていますが、CloudFormation は「すでに存在しないリソース」の削除を成功として扱うので問題ありません。
4. **リージョンが東京以外**になっていると「消すものはありません」と出ます。画面右上のリージョンを確認してください。
5. コピー＆ペーストではなく手順を目で追いたい人は、`scripts/cleanup.sh` の中身を読んでください。段階ごとにコメントを付けてあり、コンソールで同じ順に消す場合の手順にもなっています。

## コンソールだけで消す場合（CloudShell を使わない人）

| 順番 | 操作 | 場所 |
|---|---|---|
| 1 | インスタンスを「**終了**」（停止ではない） | EC2 → インスタンス |
| 2 | NAT ゲートウェイを削除し、「削除済み」になるまで待つ | VPC → NAT ゲートウェイ |
| 3 | Elastic IP を「**解放**」 | VPC → Elastic IP |
| 4 | VPC を選んで「VPC の削除」（サブネット・IGW・SG・ルートテーブルは一緒に消える） | VPC → お使いの VPC |
| 5 | スタックを「削除」（テンプレートを使った人だけ） | CloudFormation → スタック |

手順 4 で「依存関係があるので削除できません」と出たら、手順 1〜3 で消し忘れたものがダイアログに表示されます。それを消してからもう一度 4 を実行してください。
